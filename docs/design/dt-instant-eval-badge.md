# dt 即时求值徽章（S4）· 规划档

- 日期：2026-10-24 起草
- 状态：**proposed**（规划先行——本档即 A3 首里程碑，实施待下一执行轮）
- 关联：D2 列级命中统计（run-scoped，已上线 1.36.0）/ simulator debug 通路 / ADR-015 实例依赖

## 1 · 需求形态

决策表单元格在**行输入数据就位**时，即时显示该行的求值结果徽章（条件 true/false、
行是否命中），策略作者无需手动 Run all 即可看到行命中情况——把 D2 的 run-scoped
统计升格为**编辑时实时反馈**。

## 2 · 核心裁定：复用 run 通路，不自建求值器

**即时求值 = 既有 fixturesRun 通路的防抖自动重跑**，不是内核新写条件解释器：

1. **求值权威单源**：内核 dt 无自有引擎执行——求值走宿主注入 executor
   （fixturesRunner / simulateHandler，appshell 注册）。自建本地解释器必然与
   引擎编译语义分叉（dt 编译为 graph rule 节点后的求值才是权威）；
2. **免费获得全量语义**：hitPolicy（first/collect）、表达式单元、`$` 语义等
   全部由同一执行面覆盖，零重复立法；
3. **D2 资产直接复用**：traceData.rule._id → 列级命中（RunHitStatsStrip）+
   行级命中（新增）同一 trace 形状。

## 3 · 数据源与徽章形态

| 数据源 | 徽章形态 | 落点 |
| --- | --- | --- |
| simulator 输入（单行样本） | 行首条件结果 true/false 点标 + 首中行高亮 | dt 主表行头 / 条件单元角标 |
| fixtures 多行（Run all） | 既有列级命中条（RunHitStatsStrip）+ 行级命中计数 | 已上线部分，实时化即可 |

**推荐首期 = simulator 单行通路**（数据源唯一、语义最简）；fixtures 自动重跑
（多行 × 全图执行）性能面大，列二期。

## 4 · 开放问题

1. **自动重跑的触发边界**：dt 结构变更（增删行列）防抖 300-500ms 重跑 vs 仅
   参数值变更触发——结构变更重跑会闪烁，倾向「结构变更挂起徽章（灰显），
   参数变更重跑」；
2. **大表性能闸**：行数超阈值（≥100？）时即时徽章自动降级为手动 Run（与
   虚拟化可视行协同需要 executor 分页能力，宿主契约是否具备待核）；
3. **conflict 面**：即时徽章与手动 Run all 的 trace 归属（同一条 debug 通道
   还是并行通道）——倾向同一 debug state，徽章只是它的另一个消费者。

## 6 · 不做

- 内核自建条件求值解释器（语义分叉，判式同「每宿主重交学费」）；
- fixtures 多行自动重跑（二期再议，性能面未核）；
- 输出列即时求值徽标（一期只做条件侧；输出列由 simulator 面板覆盖）。
