# i18n — Internationalization Guide

Status: **wire-through complete** (commits `9b2839b`, `34cead3`, `8c8d303`, `fa85d78`, `5ddb05b`).

The editor ships locale-neutral components: every user-visible chrome string
(tooltips, context menus, placeholders, confirms, fallback UI) resolves through
the i18n layer. English is the source of truth; Simplified Chinese is bundled.

## Quick start

```tsx
import { JdmConfigProvider } from '@republicroad/seal-editor';

// zh-CN is bundled; any other locale accepts a partial message map
<JdmConfigProvider locale='zh-CN'>
  <DecisionGraph ... />
</JdmConfigProvider>

// host-supplied overrides for locales we do not bundle
<JdmConfigProvider
  locale='de'
  messages={{ 'dt.toolbar.export': 'Excel exportieren', 'common.remove': 'Entfernen' }}
>
  <DecisionTable ... />
</JdmConfigProvider>
```

Without a provider the library renders English — zero configuration is a valid
default, and no provider is required for the editor to function.

## Architecture

| Module | Role |
|---|---|
| `theming/i18n.tsx` | `I18nProvider` (injected by `JdmConfigProvider`), `useT()` hook, `createT(locale)` factory |
| `theming/messages/en.ts` | Source-of-truth catalog (190 keys, flat `'ns.key'` shape), exports `TranslationKey` |
| `theming/messages/zh-CN.ts` | Bundled Chinese catalog, key-parity locked by test |
| `theming/i18n-types.ts` | `{{param}}` interpolation helper |

- **Fallback chain**: host `messages` override → `locale` catalog → `en` → raw key.
  A missing key never throws; it renders English, then itself.
- **Keys are typed**: `useT()` accepts `TranslationKey | string`, so consumers get
  autocomplete on catalog keys while hosts can pass arbitrary override keys.
- **Interpolation**: `'{{count}} rows'` — `t('key', { count: 3 })`.

## Coverage

All chrome surfaces are wired: decision-table toolbar/menus/field editors/Excel
dialog, decision-graph panel/tabs/nodes/simulator/schema tabs, expression and
function editors, expression-builder, the custom function table (`cf.*`), and
the SafeBoundary fallback (via an internal function component — class
boundaries cannot call hooks).

No known limitations remain. Specification `renderNode` callbacks execute
inside the component render tree (they already call zustand hooks), so they
consume `useT()` directly and are locale-reactive.

## Testing

- `theming/__tests__/i18n.test.tsx` — provider resolution, override precedence,
  fallback chain, interpolation, en/zh key parity.
- Catalog parity is enforced: adding a key to `en.ts` without a `zh-CN.ts`
  entry fails CI.

## Adding a string

1. Add `'ns.key': 'English'` to `theming/messages/en.ts`.
2. Add the translation to `zh-CN.ts` (parity test guards this).
3. Consume with `const t = useT(); … t('ns.key')` inside the component.

Do not interpolate user data into keys; keys are identifiers, params are values.
