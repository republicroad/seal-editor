# ADR-000：ADR 制度宪章——立法判据、跨仓归属与评审工作流

## 状态

accepted（2026-10-08——把已经自然形成的惯例成文；触发 = verdict SaaS 线启动，
决策记录即将多仓化，归属规则必须在第一件 verdict 立法（ADR-019）之前定型）

## 背景

生态已扩为三仓：**seal-editor**（编辑器内核 + appshell）、**jdm-editor**
（zen-udf 执行内核，立法走 CONTRACT.md）、**verdict**（决策引擎 SaaS 服务，
主线刚启动）。决策记录的既有惯例运行良好但未成文：

- 编号序列 001-018 在 seal-editor `docs/adr/` **全仓共享不分线**——zen-udf
  侧决策（ADR-011/012/014-016）与消费方起草的决策（ADR-018 verdict 起草）
  均落此；
- 评审工作流已两次验证：一方起草 `proposed`，影响面对方仓评审，注记
  （事实核查 / 逐节裁定 / 精化）落档后转 `accepted`（ADR-015、ADR-018 先例）；
- jdm-editor 的执行契约沿 CONTRACT.md 立法（无独立 ADR 档）——先例稳定。

verdict 启动后决策将高频多仓化，「哪件决策立在哪、什么才值得立」若无成文
规则，会出现立法地漂移（全部塞进维护态的 seal-editor）或档案碎片化
（跨仓契约散落三仓互相找不到）。

## 决策

### §1 · 立法判据（什么才立 ADR）

同时满足两条才立：

1. **不可轻易撤回**——撤回成本随实现增长（存储 schema、公共 API 面、跨仓
   契约、安全边界）；
2. **存在真分歧**——有多个可行方案需要裁定并留下理由；无分歧的最优解直接
   实现并在 PR 说明即可。

不立：实施细节、可逆选型、实施规范/操作手册（后者进 design/ 档或 ops 文档）、
已被上位 ADR 覆盖的推导结论。

### §2 · 立法地归属（本 ADR 核心）

**判据一句话：决策是否立法「编辑器/引擎 ↔ 服务」的共享契约。**

| 归属 | 收什么 | 编号 |
| --- | --- | --- |
| **seal-editor `docs/adr/`** | 编辑器内核决策、zen-udf 引擎决策、**跨仓接口契约**（编辑器/引擎 ↔ verdict 服务的生产者/消费者契约，如模型存储与执行契约、租户治理谓词消费面） | 001 起全仓共享单一序列（跨线决策占同一序列）；000 = 本宪章特例，不参与递增 |
| **verdict 仓 `docs/adr/`** | verdict 服务**内部**架构决策（端口 Redis 化选型、部署拓扑、中间件/队列选型、服务拆分等） | 独立序列 `verdict-001` 起，仓 README 载明本规则并回链本 ADR |
| **jdm-editor CONTRACT.md** | zen-udf 执行契约的条文层（调用形态、夹具、错误码、一致性档位）——既有惯例不变 | — |

灰色地带裁决权：拿不准时**从共享契约侧**——错放 seal-editor 的代价（多一个
跨仓引用）远小于错放 verdict 仓的代价（契约半边立法漂移）。

### §3 · 评审工作流

1. 任一仓起草，状态 `proposed`（只提 ADR 不改代码，除非决策本身即文档）；
2. 影响面对应仓评审——注记落档于 ADR 尾部：事实核查（逐条对账代码/文档）、
   逐节裁定（接受 / 修改后接受 / 否决）、精化（入实施 MUST 项）；
3. 评审接受后转 `accepted`，实施条款写明归属仓与目标版本；
4. 先例：ADR-015（jdm 评审 seal 提案）、ADR-018（seal 评审 verdict 提案）。

### §3.1 · 实施归属与会话纪律（2026-10-09 增补）

**立法地 ≠ 实施会话。** ADR accepted 后，实施由**归属仓的会话**执行；需求方
仓/会话不直接写对方仓的实现代码——以新 ADR 或对既有 ADR 的修订提案协商。
理由：多会话并行开发同一仓会互相踩踏（状态标签失真、推送竞争、lint 债无人
认领）。跨仓的**接口立法与评审**（本宪章 §2 左列）不受此限——那正是需求方
仓的职责。先例：ADR-019/020（seal 立法 → verdict 实施）、ADR-018（verdict
提案 → jdm 实施）。

### §4 · 状态机与后记

`proposed → accepted → deprecated | superseded by ADR-xxx`；状态变更在正文
尾部追加「## 后记」说明原因与替代 ADR 链接（README 既有约定）。

### §5 · 与其他文档层的分工

- **ADR**：不可撤回的选型裁定（为什么这样决定）；
- **docs/design/**：详设与规格（怎么实现——ADR 的下游）；
- **jdm CONTRACT.md**：zen-udf 执行契约条文；
- **kb/**：跨项目最佳实践沉淀。
ADR 不复制以上层的内容，只引用。

## 后果

- **正面**：verdict 高频内部决策不跨仓提 PR（维护态 seal-editor 不被打扰）；
  跨仓契约保持单一档案（三仓互相找得到）；立法判据成文后「要不要立」不再
  逐件争论；
- **约束**：verdict 仓需在建仓/首件内部决策时搭最小 ADR 基础设施（目录 +
  README 回链本宪章，不要求 Pages/链接检查器对齐）；灰色地带仍会产生裁量，
  本 ADR 给出裁决权方向（§2）；
- **后续条件**：ADR-019（verdict 模型生命周期与执行契约）为本宪章下第一件
  适用件——跨仓接口契约，归 seal-editor 序列。
